01

$ cp -r skills/deep-research-ultra ~/.qoder/skills/
# Windows：xcopy /E /I skills\deep-research-ultra %USERPROFILE%\.qoder\skills\deep-research-ultra
$ python skills/deep-research-ultra/scripts/research.py --probe

03

四道机器门，不靠自觉

都是包内脚本执行的硬校验，两种用法（解包 / 插件）下同样生效。

A

证据账本

结论落成 claim，挂来源与 Tier 1–4；转载指纹算独立来源，不重复计数。 归属型断言走「一手制品 + 逐字反查」，跨域三角只给多来源立论用。矛盾记 conflict 并留处置，就地更正附 amended_at 留痕。
B

发布前校验门

主指标是引用—证据对齐：被引用立论的 claim 必须 verified 或已标冲突；引用编号不得指向不同来源。 全量覆盖率只告警不阻断——分母里含没写进报告的过程记录。
C

防伪戳

过门后 --stamp 盖上正文与账本指纹，交付前 --verify-stamp 复核。骨架里的【待写】占位过不了门。
D

Phase 0 环境闸门

--probe 逐项实测引擎出不出数据，出数据不足 3 个 / 覆盖不足 2 层 / 无一手制品通道 → 退出码 3 硬停， 并逐条打印去哪申请、解锁什么、配哪个变量。要带缺口开跑得显式加 --allow-degraded，且会强制声明数据源受限。
04

Plan → Execute → Synthesize → Reflect

主 Agent 担任 Lead，一次性并行派发子 Agent；产物逐段落盘，返回值只给短摘要。

PHASE 1

Plan 拆解

MECE 问题树，6 状态子问题机。识别查询意图，按主题生成引擎链。

PHASE 2

Execute 检索

三级级联路由派发子 Agent 并发检索；单引擎挂掉不吞掉其余引擎的结果。

PHASE 3

Synthesize 综合

CER 结构组织，CRAAP 评分，推荐等级 Adopt / Trial / Assess / Hold 与雷达图。

PHASE 4

Reflect 反思

多信号收敛：边际收益递减即停，无高优先级缺口才交付，专家团对抗补空白。

05

它刻意不做的几件事

这些是产品立场，不是待办。

不接入需绑卡的免费额度

每月有免费量但要求绑定银行卡的数据源，一概不接入、不推荐、不在引导里出现。

不把「宿主专属」报成可用

只能在 Agent 进程里生效的通道标 🤖，不计进脚本侧可用数，也不进建议的 --sources。

不把限流当高风险

仓库健康度扫描分五态，429 / 403 判 UNKNOWN 并提示配 GITHUB_TOKEN，不冒充仓库本身有问题。

不把下载成功当读到内容

PDF / LaTeX 先验魔数、篇幅、完整性与论文 ID；被网络层换成报错页不算下载成功。
