v6.8 新特性

从「搜得到」到「可溯源」

证据账本 + 分级来源 + 发布前校验门 + 环境闸门：结论必须能回指到一手来源，环境不足就先停。

🧾 证据账本（claim → source）

每条结论落成 claim，挂上来源与 Tier，可反查可更正。

  • 来源 Tier 1-4 分级，转载指纹去重算独立来源
  • 两档 verified 判据：跨域三角（A）/ 一手来源+逐字反查（B）
  • 矛盾记 conflict 并留处置，不静默丢弃
  • 就地更正 claim 原文，附 amended_at 留痕

🛡 发布前校验门

主指标是引用-证据对齐，而不是漂亮的覆盖率数字。

  • 被引用立论的 claim 必须已 verified 或已 conflict
  • 引用编号不得在登记表里指向不同来源（防串号）
  • 全量覆盖率降为告警：分母含未写进报告的过程记录
  • 正文标 ⚠️ 的降级引用只告警，不阻断交付
  • 防伪戳：过门后 --stamp 盖上正文/账本指纹，交付前 --verify-stamp 复核——没戳＝未校验
  • 下载的 PDF/LaTeX 先验魔数、篇幅、完整性与论文 ID——HTML 报错页不算下载成功
  • 仓库扫描分五态：429/403 限流判 UNKNOWN 并让配 GITHUB_TOKEN，不冒充仓库高风险

🛑 Phase 0 环境闸门

环境不足即硬停，把缺项与配置方法交给用户。

  • --probe 实测每个引擎今天出不出得来数据（杜绝 --list 假绿）
  • 出数据 <3 个 / 覆盖 <2 层 / 无一手制品通道 → 退出码 3
  • 逐条打印去哪申请、解锁什么、export 哪个变量
  • --allow-degraded 才允许带缺口开跑，并强制声明数据源受限
  • 5 个 MCP 源也进闸门：真起进程握手才算连上，超时给预热指引（v6.9）

🤝 Lead 内联编排

主 Agent 当 Lead，一次性并行派发子 Agent。

  • Plan-Execute-Synthesize-Reflect 四阶段，产物逐段落盘
  • 多视角专家团：域专家 / 怀疑者 / 实践者对抗

工作流程

Plan → Execute → Synthesize → Reflect

四阶段深度调研范式，每一步都经过优化。

01

Plan 规划

MECE 问题树分解，6 状态子问题机制作业。识别查询意图，选择最佳引擎链。

02

Execute 执行

智能路由三级级联，并发搜索多个引擎，curl_cffi TLS 伪装，Crawl4AI 浏览器自动化。

03

Synthesize 综合

CER 结构组织，CRAAP 评分验证，推荐度评分排序，SVG 雷达图可视化。

04

Reflect 反思

多信号停止：边际收益递减检测，无高优先级空白自动收敛，交叉验证补充。
