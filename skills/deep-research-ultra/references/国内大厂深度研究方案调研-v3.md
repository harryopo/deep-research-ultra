# 国内大厂深度研究方案调研报告 v3

> **调研时间**：2026-08-08
> **调研范围**：国内 10 家头部 AI 厂商的深度研究（Deep Research）方案
> **调研目标**：方法论、逻辑步骤、数据源、反思机制、输出格式、国内适配、创新点
> **应用对象**：deep-research-ultra skill（当前 v5.1）的方法论升级参考

---

## 概述

2025 年是"深度研究"（Deep Research）从概念走向产品化落地的关键一年。OpenAI 于 2025 年 2 月 3 日率先推出 Deep Research 智能体功能后，国内大厂在 2 月至 11 月期间密集跟进，形成了具有中国特色的深度研究生态。

本报告调研了 10 家代表性产品：

| 序号 | 产品 | 厂商 | 首发深度研究功能时间 |
|------|------|------|----------------------|
| 1 | Kimi 探索版 / K2 Thinking | 月之暗面 | 2024-10（探索版）/ 2025-11（K2 Thinking） |
| 2 | 秘塔 AI 深度研究 | 秘塔科技 | 2025-Q3 |
| 3 | 文心一言深度搜索 | 百度 | 2025-02-13 |
| 4 | 通义 DeepResearch | 阿里 | 2025-05-13 |
| 5 | AutoGLM 沉思 | 智谱 | 2025-03-31 |
| 6 | 豆包 DeepResearch | 字节 | 2025-06-11 |
| 7 | 混元 T1 / 元宝深度搜索 | 腾讯 | 2025-03-21 / 2025-07-01 |
| 8 | DeepSeek R1 | 深度求索 | 2025-01 |
| 9 | Perplexity Pro Search | Perplexity | 2024（海外）/ 国内仿品 |
| 10 | 天工 Skywork Deep Research Agent | 昆仑万维 | 2025-05-22 |

**核心发现**：

1. **范式分化**：国内厂商沿"先想后搜"（Plan-then-Execute）与"边想边搜"（Interleaved Thinking-Searching）两条技术路径分化，豆包、Kimi K2 Thinking、智谱 AutoGLM 沉思是后者的代表。
2. **方法论同源**：几乎所有产品都遵循 Plan→Execute→Reflect→Synthesize 的四阶段范式，与 deep-research-ultra skill v5.1 高度一致。
3. **国内独特创新**：秘塔"多线迭代追搜直至逻辑闭环"的可视化研究路径图、智谱"边想边干"的 GUI 操作能力、天工"多模态深度调研"是国内独有的差异化能力。
4. **开源生态**：DeepSeek R1（GRPO 算法）、Kimi K2 Thinking、Tongyi DeepResearch、GLM-Z1 均已开源，为 deep-research-ultra 提供了可借鉴的开源底座。
5. **反思机制趋同**：从"覆盖率达标即停"演化为"边际收益递减检测 + 无高优先级空白自动收敛"的多信号停止机制，与 Kimi 探索版的反思机制一致。

## 1. Kimi（月之暗面）

### 研究方法论

Kimi 的深度研究能力经历了从"探索版"到"K2 Thinking"的两次范式跃迁：

**第一阶段（Kimi 探索版，2024 年 10 月）**：采用"自主策略规划 + 自动化大规模信息检索 + 对搜索结果的反思与补充"三段式方法论。模拟人类推理思考过程，将复杂问题多级分解，搜索量是普通版的 10 倍，一次搜索可精读 500 个页面。其方法论本质是"工具增强的 ReAct 范式"——AI 自主决定何时搜索、搜索什么、何时停止。

**第二阶段（Kimi K2 Thinking，2025 年 11 月 6 日开源）**：基于"模型即 Agent（Model-as-Agent）"理念打造，原生掌握"边思考、边使用工具"的能力，无需外接 Agent 框架。模型本身内化了工具调用决策，可在无人干预的情况下连续执行 200-300 轮工具调用与多轮思考。这是从"ReAct 外挂"到"内生 Agent"的根本性转变。

### 逻辑步骤

**探索版流程**：
1. 用户提问
2. 自主策略规划：分解复杂问题为子问题
3. 自动化大规模信息检索：一次精读 500 页
4. 反思与补充：评估结果完整性，不足则补充搜索
5. 输出综合答案

**K2 Thinking 流程**（执行回路式）：
1. 用户提问（可通过 prompt 引导深度探索）
2. 模型原生推理（thinking token 流式输出）
3. 识别信息缺口 → 调用工具（搜索/代码/浏览）
4. 阅读工具返回 → 反思信息是否充分
5. 不充分则发起新一轮搜索（最多 300 轮）
6. 满足终止条件后综合输出

### 数据源

- 互联网公开网页（自主搜索，10 倍搜索量）
- 可调用工具：搜索、代码执行、3D 程序生成等
- 在 Claude Code / OK Computer 模式下可调用更丰富工具

### 多轮反思机制

Kimi K2 Thinking 的反思机制是其核心创新，参考实测用法：

```
Prompt 引导："我需要你深度探索本问题，每次搜索获得信息后，
都去审视当前的所获取信息的不足之处，并发起新一轮搜索。
整个过程至少重复 10 轮。"
```

**多信号停止判据**：
1. 信息覆盖度达标
2. 无高优先级信息空白
3. 边际收益递减（继续搜索的增量信息价值下降）
4. 达到最大轮次（300 轮硬上限）

这种"执行回路"式 prompt 与 deep-research-ultra v5.1 的 `reflect.py` 多信号停止机制高度同构——这正是 v5.1 落地"Kimi 多信号停止"的来源。

### 输出格式

- 流式思考链可视化（thinking tokens 实时显示）
- 工具调用过程透明展示
- 最终结构化答案
- 支持 INT4 推理（开源版）

### 国内适配

- 国产模型，原生中文优化
- 在 Humanity's Last Exam、BrowseComp、SEAL-0 等 Agentic 基准取得 SOTA
- 开源版支持本地部署，规避国内网络访问海外 API 的限制

### 与 OpenAI Deep Research 的差异

| 维度 | OpenAI Deep Research | Kimi K2 Thinking |
|------|---------------------|------------------|
| 范式 | Agent 外挂工具调用 | 模型即 Agent（内生能力） |
| 最大轮次 | ~100 轮 | 300 轮 |
| 开源 | 否 | 是（INT4） |
| 反思 | 启发式 | 原生反思能力 |

### 可借鉴点（代码级建议）

1. **`reflect.py`**：当前已实现"边际收益递减检测"，可进一步引入 Kimi 式的"执行回路 prompt"机制——在 reflect 阶段动态生成下一轮搜索 prompt，而非固定模板。
2. **`plan.py`**：考虑引入"模型即 Agent"模式，让 LLM 在 plan 阶段就原生决定工具调用序列，而非通过 if-else 硬编码。
3. **`research.py`**：增加 `--max-rounds 300` 参数，对标 K2 Thinking 的硬上限。

## 2. 秘塔 AI

### 研究方法论

秘塔 AI 是国内首个免费公开可用的 Deep Research 产品，采用"多线迭代追搜直至逻辑闭环"的方法论。其官网明确三种模式：

- **先想后搜（Plan-then-Search）**：先思考框架，再搜索整合资料
- **先搜后扩（Search-then-Expand）**：先搜索信息，再扩展延伸
- **深度研究（Deep Research）**：多线迭代追搜直至逻辑闭环

核心创新是"逻辑闭环"作为停止判据——不是简单的覆盖率达标，而是研究路径上的逻辑链条是否完整闭合。这比 Kimi 的"边际收益递减"更进一步，引入了"逻辑完整性"维度。

### 逻辑步骤

实测流程（以新智元评测的"苏轼-王鹤棣"问题为例）：

1. 用户提问（涉及文学史、地理、娱乐圈的多跳推理）
2. **思考阶段**：在 UI 左侧展示"诗词人与顶流男星的关联线索"思考过程
3. **多线搜索**：并发搜索苏轼科举考试、梅尧臣姓氏、眉山地理位置、乐山出生男星
4. **证据链构建**：每条信息附带来源编号（如 `[1]`、`[15]`、`[22]`）
5. **冲突解决**：对"西南航空专修学院成立年份"的 2004 vs 1985 两派观点，基于证据权重选择多数来源支持的 2004 年
6. **逻辑闭环验证**：验证"苏轼→眉州→乐山→王鹤棣→西南航空专修学院→2004年"的逻辑链是否完整
7. **生成互动研究报告**：可视化证据链展示网

### 数据源

- 全网网页搜索
- 学术资料（含论文 PDF）
- 文库资源
- 在 BrowseComp-zh 评测集取得 45.33 分（超越 WebSailor-32B 的 40 分）

### 多轮反思机制

秘塔的反思机制体现在 UI 上的"研究路径图"：

```
┌─────────────────────────────────────────┐
│ BURN: 113293 tokens                      │
│ SOURCES: 180 sources                     │
│ REMAINING: 100 credits                   │
│ TIME: 7.8 min                             │
├─────────────────────────────────────────┤
│ 思考过程（滚动展示）：                    │
│ - 硅基化合物在高压高温和液态甲烷环境中... │
│ - 具体热力学优势和局限性是什么？          │
│ - 2020-2025年天体化学领域突破？           │
│ - What spectroscopic evidence...          │
└─────────────────────────────────────────┘
```

**MetaAI.Thinking() → MetaAI.Report()** 两阶段分离，思考阶段生成下一轮搜索 query，报告阶段综合输出。

### 输出格式

- **互动研究报告**：可视化证据链展示网（"透明大脑"）
- **PDF 导出**：支持生成带引用编号的 PDF
- **表格对比**：如元素特性对比表（硼/碳/硅）
- **结构化分章节**：引言→多部分分析→结论
- 实时显示 token 消耗、信源数、剩余 credits、耗时

### 国内适配

- 国内首个免费 Deep Research，无广告直达结果
- 中文信息场景深度优化
- 学术搜索适配中国知网等本土源
- UI 设计针对中文阅读习惯优化

### 与 OpenAI Deep Research 的差异

| 维度 | OpenAI | 秘塔 AI |
|------|--------|---------|
| 可视化 | 线性界面 | 证据链展示网（"透明大脑"） |
| 停止判据 | 固定轮次/覆盖率 | 逻辑闭环 |
| 价格 | 付费（Pro） | 免费 |
| 中文优化 | 一般 | 原生中文 |

### 可借鉴点（代码级建议）

1. **`plan.py`**：引入"逻辑闭环"状态——除现有 6 状态（pending→searching→verified/conflict/supplementing→completed）外，增加 `logical_closure_check` 方法，验证子问题间的逻辑链条是否闭合。
2. **`report.py`**：增加"证据链可视化"输出格式——生成 Mermaid 流程图或 HTML 互动报告，展示来源间的引用关系。
3. **`research.py`**：在 CLI 输出中实时显示 token 消耗、信源数、耗时，提升用户感知。
4. **`reflect.py`**：引入"冲突解决"模块——当多来源信息冲突时，基于来源权威性权重自动选择。

## 3. 百度文心一言

### 研究方法论

百度文心一言于 2025 年 2 月 13 日上线"深度搜索"功能，4 月 1 日起全面免费。官方定位为"专家级内容回复"，核心方法论是"思考规划 + 工具调用 + 多模态输入输出"三位一体。

不同于纯 LLM 调研，文心一言深度搜索的独特之处在于**深度整合代码解释器**——搜索获取的结构化数据（如财务报表、政策条款）会传入代码解释器做确定性推理（计算复合增长率、生成图表），最后输出格式化报告。这种"搜索 + 代码执行"的双引擎模式，有效解决了纯 LLM 在数值计算上的幻觉问题。

### 逻辑步骤

以"北京买房贷款政策对比分析"实测案例为例：

1. 用户提问（含多重要求：最新政策、具体条款变化、对比表格）
2. **思考规划**：分解为"央行文件查询 + 历史数据对比 + 表格生成"子任务
3. **联网搜索**：检索最新央行文件、公积金政策
4. **长文档阅读**：解析政策原文 PDF
5. **大海捞针**：在长文档中定位具体条款变化
6. **深度推理**：代码解释器计算利率变化、额度差异
7. **格式化输出**：生成对比分析表格

### 数据源

- 百度搜索（自家搜索引擎，中文覆盖最广）
- 长文档处理（支持超长文档上传）
- 专业检索增强（Professional Retrieval Augmented）
- 多模态输入：图片、PDF、Excel 财务报表

### 多轮反思机制

文心一言深度搜索的反思机制相对隐性，主要体现为：

- 搜索结果质量评估（通过引用来源可信度）
- 代码解释器验证数值正确性（消除幻觉）
- 多场景任务适配（自动选择搜索/文档/代码路径）

但缺乏显式的多轮迭代追搜机制，更偏向"一次性深度执行"。

### 输出格式

- **结构化分析报告**：含执行摘要、分章节分析、结论
- **数据可视化图表**：柱状图、折线图、趋势线叠加
- **对比分析表格**：支持多维度对比
- **多模态输出**：文字 + 图表 + 表格组合

### 国内适配

- 依托百度搜索生态，中文内容源覆盖最广
- 适配中文专业内容匮乏现状，"专业信息平权"定位
- 多语种对话支持
- 高级 AI 绘画、多模态对话集成

### 与 OpenAI Deep Research 的差异

| 维度 | OpenAI | 文心一言 |
|------|--------|---------|
| 代码执行 | 有（Advanced Data Analysis） | 有（深度整合） |
| 搜索引擎 | Bing | 百度（中文优势） |
| 多模态 | 文本+图像 | 文本+图像+表格+图表生成 |
| 价格 | Pro 付费 | 免费 |

### 可借鉴点（代码级建议）

1. **`execute.py`**：引入代码解释器子 Agent——在数值计算、图表生成场景调用 Python 执行环境，消除 LLM 数值幻觉。
2. **`report.py`**：增加"图表自动生成"能力——根据报告内容自动生成柱状图、折线图、对比表格。
3. **`router.py`**：在九类查询基础上增加"数值计算"类，路由到代码解释器。
4. **`academic_fulltext.py`**：借鉴百度的"长文档处理"能力，增强 PDF 全文解析的章节定位精度。

## 4. 阿里通义千问 DeepResearch

### 研究方法论

通义千问于 2025 年 5 月 13 日在 QwenChat 上线 Deep Research，免费开放。其方法论深度融合了 Qwen 模型的三大能力：**推理能力 + Agent 能力 + 长上下文窗口能力**，并结合强化学习方法实现"从理解需求到交付成果"的研究闭环。

2025 年 9 月 17 日，阿里开源 Tongyi DeepResearch（前身 WebAgent 项目），在 HLE、BrowseComp-zh、GAIA 等权威评测集上取得 SOTA，超越 OpenAI 同类产品。这是国内首个开源的深度研究 Agent 模型。

2025 年 11 月 14 日发布的 2511 版本引入**双模式运行机制**：
- **Normal 模式**：高效通用，快速处理常规研究任务
- **Advanced 模式**：专业研究，强化推理引擎 + 优化引用溯源 + 扩展数据覆盖

### 逻辑步骤

1. **用户 prompt 输入**
2. **反问确认**：通过反问方式进一步确认任务具体细节（clarification）
3. **制定多步骤研究计划**：分解任务为子步骤
4. **查找、分析、整合网络信息**：多步骤搜索
5. **生成易读报告**

### 数据源

- 互联网海量信息（综合搜索）
- 2511 版本资料库规模扩大 40%
- 引用溯源算法优化（2511 版本引用可靠性 +35%）

### 多轮反思机制

通义 DeepResearch 的反思机制体现在：
- 多步骤搜索的迭代评估
- 引用可靠性增强（2511 版本 +35%）
- 抗干扰能力提升（2511 版本 +28%）
- 内容完整度检测（2511 版本 +31%）

开源版 Tongyi DeepResearch 基于强化学习训练，具备端到端的反思能力。

### 输出格式

- 全面、易读的报告形式
- 引用溯源标注
- 结构化分章节
- 2511 版本指令执行准确率达 92%

### 国内适配

- 阿里集团 AI 战略协同，移动端"通义"系列统一更名为"Qwen"
- iOS 与安卓双平台更新
- 中文场景深度优化
- 开源生态（Tongyi DeepResearch）

### 与 OpenAI Deep Research 的差异

| 维度 | OpenAI | 通义 DeepResearch |
|------|--------|------------------|
| 开源 | 否 | 是（Tongyi DeepResearch） |
| 双模式 | 单一 | Normal/Advanced 双模式 |
| 评测 | HLE/GAIA 强 | HLE/BrowseComp-zh/GAIA SOTA |
| 价格 | Pro 付费 | 免费 |

### 可借鉴点（代码级建议）

1. **`research.py`**：引入"双模式"参数 `--mode normal|advanced`，Normal 模式跳过反思循环直接输出，Advanced 模式启用完整 Plan-Execute-Reflect-Synthesize 流程。
2. **`plan.py`**：增加"反问确认"环节——在 MECE 拆解前，通过 AskUserQuestion 反问用户确认任务细节（当前 v5.1 已有主题澄清，可强化为多轮反问）。
3. **`reflect.py`**：引入"抗干扰能力"指标——对低质量来源降权，2511 版本的 +28% 抗干扰提升值得借鉴。
4. **`router.py`**：增加"引用可靠性"评分维度，对标 2511 版本的 +35% 提升。

## 5. 智谱 ChatGLM / AutoGLM 沉思

### 研究方法论

智谱于 2025 年 3 月 31 日中关村论坛发布 AutoGLM 沉思，是国内首个集深度研究能力和操作能力于一体的 Agent。核心方法论是"边想边干"（Think-while-Acting），区别于传统"先想后干"。

AutoGLM 沉思背后是智谱 GLM 全栈自研大模型，技术路径历经四代演进：
1. **GLM-4 基座模型**（通用能力）
2. **GLM-Z1 推理模型**（反思能力，性能比肩 DeepSeek-R1，速度提升 8 倍，价格仅 1/30）
3. **GLM-Z1-Rumination 沉思模型**（沉思能力）
4. **AutoGLM 模型**（自动执行能力）

这四个模型通过强化学习融合，让模型学会自我批评、反思，甚至"沉思"，从而实现长程推理和任务执行。

### 逻辑步骤

AutoGLM 沉思的深度思考机制包含四个关键环节：

3. **推理与决策**：在执行过程中，不断进行推理和决策，调整行动方案
4. **反思与优化**：任务完成后，进行反思和总结，优化未来的处理方式

**关键差异化**：不仅能访问普通搜索引擎的公开信息，还能处理**需要登录的网站**（知网、知乎、微信公众号），通过模拟人类操作（GUI 自动化）扩展信息获取范围。

AutoGLM 沉思的反思机制基于三大关键特性：
1. **深度思考**：模拟人类推理与决策过程

## 8. DeepSeek R1

### 研究方法论

DeepSeek R1 于 2025 年 1 月开源，性能对标 OpenAI o1。其方法论本质是"通过纯强化学习提升大模型推理能力"，关键创新是 **GRPO（Group Relative Policy Optimization，群体相对策略优化）** 算法。

DeepSeek R1 的核心功能：**深度推理、广泛探索、可行反思**。它是长链思考大模型，产生比浅层短思维链更高效、连贯的结果。

### 逻辑步骤

DeepSeek R1 采用**多阶段训练流程**：

1. **Step-1：SFT 冷启动**：基于少量高质量推理数据微调 Base 模型
2. **Step-2：面向推理的大规模 RL**：使用 GRPO 算法进行强化学习
3. **Step-3：再次构建大规模训练数据**：基于 RL 后的模型生成高质量数据
4. **Step-4：对 Base 再做一次大规模 SFT**：用新数据微调
5. **Step-5：第二轮 RL（全场景）**：覆盖通用任务

**R1-Zero 变体**：直接从 Base 模型进行大规模 RL，跳过 SFT，纯强化学习训练，验证了"无监督微调也能涌现推理能力"。

### 数据源

DeepSeek R1 本身是推理模型，不直接绑定搜索数据源。但其思维链能力被广泛应用于：
- 数学推理（MATH-500：97.3 分）
- 编程（Codeforces：超越 96.3% 人类选手）
- 通用逻辑推理（MMLU-PRO：87 分）

### 多轮反思机制

GRPO 算法是 DeepSeek R1 反思能力的核心：

**GRPO vs PPO 的本质区别**：
- **PPO**：维护与策略模型规模相近的价值网络，计算开销大
- **GRPO**：用群体相对奖励（基于组内奖励均值和标准差）衡量个体表现，消除绝对奖励干扰，无需价值函数模型

**GRPO 流程**：
1. 采样：为每个 prompt 生成 G 个输出
2. 奖励评分：对每个输出评分
3. 计算群体统计量：均值 μ + 标准差 σ
4. 计算相对奖励：A_i = (R_i - μ) / (σ + ε)
5. 优化目标函数：J_GRPO(θ) = 提升 team 整体表现 - 控制新规则变动

**涌现能力**：R1-Zero 自发涌现出"子问题结构拆解、自反思"能力，这是 PPO 无法复现的。

### 输出格式

- **思维链可视化**：网页端点击"深度思考(R1)"按钮、App 端开启圆形 R1 开关、命令行添加 `--think` 参数
- 长链思考过程流式展示
- 最终答案与思考过程分离

### 国内适配

- 国产开源模型，MIT 协议
- API 定价极低（输入 1 元/百万 tokens）
- 国内各大平台（腾讯元宝、字节豆包、Kimi 等）均接入 DeepSeek R1
- 百元级复现方案（X-R1 项目）

### 与 OpenAI Deep Research 的差异

| 维度 | OpenAI o1 | DeepSeek R1 |
|------|-----------|-------------|
| 训练方法 | 未公开 | GRPO + 多阶段 |
| 开源 | 否 | 是（MIT） |
| 价格 | 高 | 极低 |
| 思维链 | 隐藏 | 可视化 |

### 可借鉴点（代码级建议）

1. **`reflect.py`**：引入 GRPO 式的"群体相对评估"——对多轮搜索结果进行组内相对评分，而非绝对评分，减少奖励尺度干扰。
2. **`plan.py`**：借鉴 R1-Zero 的"涌现式子问题拆解"——允许 LLM 在 Plan 阶段动态生成子问题树，而非依赖模板。
3. **`research.py`**：增加 `--think` 参数控制思维链可视化输出。
4. **整体架构**：参考 R1 的多阶段训练流程，为 deep-research-ultra 设计"冷启动 SFT → 推理 RL → 数据重建 → 全场景 RL"的自优化闭环。

### 3. `reflect.py` — 反思阶段增强

**3.1 引入 GRPO 式群体相对评估（借鉴 DeepSeek R1）**
```python
# 当前：绝对覆盖率评估
# 改进：对多轮搜索结果进行组内相对评分
def grpo_evaluate(results):
    rewards = [score(r) for r in results]
    mean_r = mean(rewards)
    std_r = std(rewards)
    relative_rewards = [(r - mean_r) / (std_r + epsilon) for r in rewards]
    return relative_rewards
```

**3.2 强化"边际收益递减检测"（对标 Kimi K2 Thinking）**
```python
# 当前已有：Δ覆盖率 < 0.05 且覆盖率 ≥ 0.6 → 收敛
# 改进：增加多信号停止判据
def should_stop(reflect_state):
    signals = [
        coverage_threshold_met(reflect_state),  # 覆盖率达标
        no_high_priority_gap(reflect_state),    # 无高优先级空白
        diminishing_returns(reflect_state),    # 边际收益递减
        logical_closure_verified(reflect_state),# 逻辑闭环验证（新增）
        max_rounds_reached(reflect_state, 300) # 最大轮次（对标 K2 Thinking）
    ]
    return any(signals[:3]) or all(signals[3:])
```

**3.3 增加"自我批评"维度（借鉴 GLM-Z1-Rumination）**
