# 深度研究开源项目调研报告 v3

> 调研时间：2026-08-08
> 调研范围：国内外深度研究（Deep Research）相关开源项目
> 调研目的：为 deep-research-ultra skill 的架构设计与功能增强提供参考

---

## 概述

深度研究（Deep Research）是 2025 年以来 AI Agent 领域最热门的应用方向之一。自 OpenAI 在 2025 年 2 月推出 Deep Research 功能后，开源社区迅速跟进，涌现出一批高质量的开源深度研究项目。这些项目的核心共性是：以 LLM 为大脑、以搜索引擎为眼睛、以反思循环为自我纠偏机制，通过 Plan-Execute-Reflect 的迭代闭环，对复杂课题进行多源、多轮、多视角的研究，最终输出带引用的结构化报告。

本次调研覆盖 13 个项目，按星标量与影响力分为三档：

- **高星旗舰项目**（4 个）：GPT Researcher、open_deep_research、STORM、DeerFlow
- **中低星特色项目**（6 个）：deep-research（dzhng）、local-deep-researcher、node-DeepResearch（Jina）、Agentic-Reasoning、OpenResearcher、DeepResearchAgent
- **综述与模型类**（3 个）：Deep-Research-Survey、阿里通义 DeepResearch、node-llm-guide 深度研究

调研发现，当前开源深度研究项目呈现以下趋势：方法论趋同（Plan-Execute-Reflect 迭代循环已成事实标准）、数据源多样化（从单一 Tavily 扩展到 10+ 搜索引擎加学术源加 MCP 生态）、反思机制深化（从简单"是否充分"判断进化到树状递归探索加多智能体辩论）、本地化与隐私（local-deep-researcher 等推动完全本地运行）、评测标准化（Deep Research Bench 成为事实标杆）。

## 1. GPT Researcher

### 基本信息

| star | 语言 | 最后更新 | 许可证 | commits |
|------|------|----------|--------|---------|
| ~22k+ | Python | 2026-07-14 | Apache-2.0 | 3,077 |

### 架构设计

GPT Researcher 是最早、最知名的深度研究开源项目，由 Assaf Elovic 创建。其核心架构采用 Planner + Execution Agents + Publisher 的三段式设计。Planner（规划器）根据用户查询生成研究问题列表，形成多角度的客观研究框架。Execution Agents（执行代理）为每个问题并行爬取网页信息，进行摘要与来源追踪。Publisher（发布器）聚合所有摘要，过滤去重，生成最终研究报告。数据流为：用户查询到规划器生成问题到执行代理并行爬取到摘要与来源追踪到过滤聚合到最终报告。

项目目录结构清晰：gpt_researcher（核心库）、multi_agents（多智能体）、deep_agents（深度研究）、backend（FastAPI 服务）、frontend（NextJS + Tailwind）、skills/gpt-researcher（Claude Skill）、evals（评测集）。MCP server 已独立为 gptr-mcp 仓库。

### 研究方法论

采用 Plan-and-Solve 论文（arxiv:2305.04091）和 RAG（arxiv:2005.11401）思想。特色功能是 Deep Research 递归树状探索：树状探索可配置深度（depth）和广度（breadth），并发处理加速结果，跨研究分支的智能上下文管理，单次深度研究约 5 分钟，单次成本约 $0.4（使用 o3-mini，high reasoning effort）。

### 数据源

集成超过 20 个数据源，默认使用 Tavily。还支持 MCP 混合检索（RETRIEVER=tavily,mcp），可接入 GitHub、数据库等自定义 API。最新版本新增 GetXAPI 用于 X/Twitter 搜索。通过 OPENAI_BASE_URL 可接入任意 OpenAI 兼容 API。

### 多智能体设计

multi_agents 目录基于 LangGraph 和 AG2（原 AutoGen）框架实现多智能体协作，灵感来自 STORM 论文。平均一次运行可生成 5-6 页研究报告（PDF/Docx/Markdown 多格式）。角色分工：Planner、Researcher、Reviewer、Writer、Publisher。

### 反思机制

通过 Deep Research 的递归树状探索实现：每个分支评估信息充分性，不充分则递归深入子主题。支持上下文跨分支传递，避免重复研究。

### 输出格式

支持 PDF、Word、Markdown 等格式导出，报告超过 2000 字。特色功能：AI 生成内联插图（Google Gemini / Nano Banana），在研究阶段预生成 2-3 张相关图像，嵌入报告。还支持智能图片爬取与过滤。

### 可借鉴点

1. Planner-Executor-Publisher 三段式架构：职责清晰，易于测试和扩展
2. 递归树状 Deep Research：可配置 depth/breadth，平衡深度与成本
3. MCP 混合检索：一行配置启用 Web + 私有数据源
4. Claude Skill 集成：npx skills add 一键安装
5. 内联图像生成：报告视觉化，区别于纯文本输出
6. 本地文档研究：DOC_PATH 支持多种格式本地语料
7. LangSmith 追踪：可观测性内置
8. evals 目录：自带评测集，含延迟跟踪和结构化 JSON 日志

## 2. open_deep_research

### 基本信息

| star | 语言 | 最后更新 | 许可证 | commits |
|------|------|----------|--------|---------|
| ~中等 | Python 69.6% / Jupyter 30.4% | 2026-05-26 | MIT | 212 |

### 架构设计

LangChain 官方出品的深度研究项目，基于 LangGraph 构建。2025 年 7 月推出 V2 Deep Research Agent（PR #134），是对原实现的重大重构。架构核心是 LangGraph 状态图驱动的 Plan-Execute-Reflect 工作流。项目包含两套 legacy 实现（src/legacy/）：Workflow 实现（Plan-and-Execute 结构化工作流加人机协作规划加顺序处理加反思迭代加交互式控制）和 Multi-Agent 实现（Supervisor-Researcher 架构加并行处理加 MCP 广泛集成加速度优化）。

### 研究方法论

采用多模型分工策略，不同环节使用不同模型以平衡成本与质量：Summarization 用 openai:gpt-4.1-mini 摘要搜索结果，Research 用 openai:gpt-4.1 驱动搜索代理，Compression 用 openai:gpt-4.1 压缩研究发现，Final Report 用 openai:gpt-4.1 撰写最终报告。模型需支持结构化输出和工具调用。支持 OpenRouter 和 Ollama 本地模型。

### 数据源

默认使用 Tavily。完全兼容 MCP，支持 Anthropic 和 OpenAI 的原生 Web 搜索。通过 configuration.py 的 search_api 和 mcp_config 字段灵活配置。

### 反思机制

V2 版本的核心创新。通过 LangGraph 状态图实现迭代反思：研究到压缩到评估充分性到不充分则补充搜索。Compression 环节是关键——将冗长的研究发现压缩为精炼上下文，避免 token 溢出。

### 评测体系

这是该项目最大的亮点——与 Deep Research Bench 深度集成：100 个 PhD 级研究任务（50 英文 + 50 中文），覆盖 22 个领域，使用 RACE 评分（LLM-as-a-judge，Gemini 评估）。项目排名第 6，总分 0.4344，GPT-5 配置下达到 0.4943（成本约 $46，2 亿 token）。评测结果表展示了不同模型组合的成本-质量权衡，极具参考价值。

### 输出格式

结构化报告，带引用。通过 LangGraph Studio UI 交互。

### 可借鉴点

1. 多模型分工策略：各环节用不同模型，成本优化典范
2. Compression 环节：独立的研究发现压缩步骤，解决长上下文 token 溢出
3. Deep Research Bench 集成：标准化评测，量化研究质量
4. 双 Legacy 实现并存：Workflow（质量优先）vs Multi-Agent（速度优先）
5. 人机协作规划：允许用户审批和反馈报告计划
6. LangGraph Platform 部署：一键云端部署
7. Open Agent Platform 集成：非技术用户也能配置自定义 Agent

## 3. STORM

### 基本信息

| star | 语言 | 最后更新 | 许可证 | commits |
|------|------|----------|--------|---------|
| ~高（70,000+ 人试用在线版） | Python | 2025-10-01 | MIT | 238 |

### 架构设计

斯坦福大学（Stanford Oval）出品的学术研究系统，论文发表于 arxiv:2402.14207。核心创新是将研究过程分解为"提问"的艺术——认为自动化研究的关键在于自动提出好问题。STORM 两阶段架构：Pre-writing Stage（预写阶段）进行互联网研究，收集参考文献，生成大纲；Writing Stage（写作阶段）基于大纲和参考文献，生成带引用的完整长文。

### 研究方法论

STORM 的两大核心策略：Perspective-Guided Question Asking（视角引导提问）——给定主题，通过调研相似主题的已有文章来发现不同视角，用这些视角控制提问过程，提升问题的深度和广度。Simulated Conversation（模拟对话）——模拟维基百科编辑与主题专家的对话，基于互联网资源进行，使 LLM 能持续更新对主题的理解并提出追问。

### Co-STORM 协作扩展

Co-STORM（论文 arxiv:2408.15232，EMNLP 2024）进一步引入协作式话语协议：Co-STORM LLM 专家基于外部知识源生成答案或提出追问，Moderator 基于检索器发现但未被直接使用的信息生成发人深省的问题，人类用户可观察对话或主动注入话语引导讨论方向。Co-STORM 还维护动态更新的思维导图（Mind Map），将收集的信息组织成层次化概念结构，建立人机共享概念空间，降低长对话的认知负荷。

### 数据源

STORM 支持的检索模块最为丰富（10 种）：YouRM（You.com）、BingSearch（微软 Bing）、VectorRM（用户自有文档向量化）、SerperRM（Serper API）、BraveRM（Brave 搜索）、SearXNG（自托管元搜索）、DuckDuckGoSearchRM（DuckDuckGo）、TavilySearchRM（Tavily）、GoogleSearch（Google）、AzureAISearch（Azure AI 搜索）。

### LLM 集成

通过 litellm 集成所有主流 LLM。STORM 采用多 LM 系统——不同组件用不同模型平衡成本与质量：conv_simulator_lm 用便宜快速的 gpt-3.5，question_asker_lm 用 gpt-3.5，outline_gen_lm 用 gpt-4o，article_gen_lm 用 gpt-4o，article_polish_lm 用 gpt-4o。

### 反思机制

通过 Simulated Conversation 实现隐式反思：专家回答后，编辑基于新信息提出追问，形成持续深入的研究闭环。Co-STORM 的 Moderator 主动发现信息缺口，生成补充问题。

### 输出格式

维基百科风格的长篇文章，带引用。支持 PDF 下载。do_polish_article 步骤会添加总结章节并去除重复内容。

### 可借鉴点

1. 视角引导提问：从相似主题发现多视角，控制提问质量——最有价值的创新
2. 模拟对话研究：编辑-专家对话模型，比单次提问更深入
3. 思维导图（Mind Map）：层次化知识组织，降低长研究认知负荷
4. 10 种检索器：最丰富的数据源集成，特别是 VectorRM 支持用户自有文档
5. 多 LM 分工：5 个不同环节用不同模型，精细的成本-质量平衡
6. dspy 框架：使用 dspy 实现高度模块化，便于定制
7. Co-STORM 人机协作：人类可随时注入话语引导研究方向
8. 两阶段分离：预写（研究）与写作分离，各阶段可独立优化

## 4. DeerFlow

### 基本信息

| star | 语言 | 最后更新 | 许可证 | commits |

| ~75k | Python + TypeScript | 2026-08-07 | MIT | 2,923 |

### 架构设计

字节跳动出品的深度研究框架。重要：DeerFlow 2.0 是完全重写，与 1.x 共享零代码。1.x 分支（main-1.x）是原来的 Deep Research 框架，2.0 已转型为 Super Agent Harness（超级智能体编排框架）。DeerFlow 2.0 核心架构：编排 Sub-Agents（子智能体）加 Memory（记忆）加 Sandboxes（沙箱）来处理需要几分钟到几小时才能完成的复杂任务，由可扩展 Skills 系统驱动。目录结构包含 backend（Python 后端）、frontend（前端）、contracts（事件流契约）、skills/public（公共技能）、plans（计划）、deploy/helm（Helm 部署）。

### 研究方法论（1.x Deep Research）

1.x 版本的 DeerFlow 采用经典的 Plan 到 Research 到 Report 流程，集成多种搜索源和 MCP 工具。2.0 虽然转型为通用 Super Agent，但 Deep Research 作为核心 Skill 之一保留。

### 数据源

集成字节跳动自研的 InfoQuest（BytePlus 智能搜索与爬取工具集），支持免费在线体验。这是 DeerFlow 区别于其他项目的独特优势——自有搜索基础设施。

### 多智能体设计

2.0 的核心特性：Sub-Agents（子智能体）顶层 Agent 协调多个专门子 Agent，任务卡显示有效模型和 token 使用。Long-Term Memory（长期记忆）使用官方 OpenViking 适配器，任务级数据与长期记忆隔离。Sandbox and File System（沙箱与文件系统）E2B 沙箱，Kubernetes 沙箱供给。Skills and Tools（技能与工具）可扩展技能系统，含技能评审质量门禁。

### 反思机制

2.0 通过 Sub-Agent 协作和记忆系统实现隐式反思。refactor(memory) 系列提交表明记忆管理是持续优化的重点——防止任务级数据进入长期记忆，保证研究质量。

### 输出格式

多格式报告，前端支持 Browser Live 实时预览。

### LLM 集成

最丰富的模型支持：CLI-backed Providers（Codex CLI gpt-5.4、Claude Code OAuth claude-sonnet-4.6）、OpenAI 兼容（支持 use_responses_api 路由）、OpenRouter（网关式接入）、vLLM（本地部署，支持 Qwen3 等推理模型的 enable_thinking）。推荐模型：Doubao-Seed-2.0-Code、DeepSeek v3.2、Kimi 2.5。

### 可观测性

集成三大追踪系统：LangSmith Tracing、Langfuse Tracing、Monocle Tracing（Agent 可观测性）。

### 可借鉴点

1. Super Agent Harness 定位：从单一 Deep Research 进化为通用复杂任务编排框架，Deep Research 成为可插拔 Skill
2. 长期记忆与任务隔离：OpenViking 适配器，任务数据不污染长期记忆
3. 沙箱系统：E2B + Kubernetes 双沙箱，安全执行代码和数据操作
4. Skills 质量门禁：技能评审机制，保证扩展质量
5. CLI-backed Providers：直接复用 Codex CLI / Claude Code 的 OAuth 认证
6. vLLM 推理模型支持：enable_thinking + cumulative_stream_usage 处理
7. InfoQuest 自有搜索：不依赖第三方搜索 API 的基础设施
8. IM Channels：Buzz (Nostr) 等渠道连接器，研究成果可多渠道分发
9. make doctor / make support-bundle：内置环境诊断和问题报告工具
10. 多语言 README：中英日法俄五语

## 7. node-DeepResearch（Jina AI）

### 基本信息

| star | 语言 | 最后更新 | 许可证 | commits |
|------|------|----------|--------|---------|
| ~高 | TypeScript / Node.js | 2026-05-02 | Apache-2.0 | 571 |

### 架构设计

Jina AI（hanxiao）出品的深度研究项目，核心理念独树一帜：不优化长篇报告，专注迭代式找到正确答案。这与 GPT Researcher/STORM 的"生成长报告"路线形成鲜明对比。核心循环为 Search 到 Read 到 Reason 再回到 Search 的迭代，直到找到答案或 token 预算耗尽。

### 研究方法论

Token Budget 驱动的迭代循环：持续搜索、阅读网页、推理，直到找到答案或 token 预算耗尽。作者强调这与 OpenAI/Gemini/Perplexity 的 Deep Research 不同——后者优化长文生成，本项目优化答案正确性。

### 数据源

使用 Jina Reader 进行搜索和阅读网页（免费 1M token）。支持 Gemini（gemini-2.0-flash）/ OpenAI / LocalLLM。

### 输出格式

简洁答案加引用。引用采用 GitHub-flavored markdown footnote 格式（如 [^1], [^2]）。提供 jina-deepsearch-v1 模型，完全兼容 OpenAI API schema。引入特殊 think 标签包裹推理步骤，将思考过程与最终答案分离。

### API 服务

提供 OpenAI-compatible API server（npm run serve），可被任何 OpenAI 兼容客户端调用。支持流式响应（stream: true），thinking 内容包裹在特定标签中。

### 可借鉴点

1. Search-Read-Reason 极简循环：最精炼的 Deep Research 范式，token budget 驱动终止条件
2. 答案优先 vs 报告优先：明确区分"找正确答案"和"生成长报告"两类需求
3. OpenAI-compatible API：一行 npm run serve 即可作为 Deep Search 服务
4. Jina Reader 集成：免费的搜索加阅读一体化方案
5. 特殊 token 设计：think 标签分离推理与答案
6. hostname 黑白名单过滤：可控制搜索范围
7. Arxiv 搜索功能：学术文献检索集成
8. 实践指南博客：作者写了详细的实现指南（中英日三语），极具学习价值

## 低星项目中的创新点

### 1. Token Budget 驱动终止（node-DeepResearch）
不同于"固定轮次"或"LLM 判断是否充分"，Jina 用 token 预算作为硬性终止条件——简单、可预测、可控成本。这避免了 LLM 自我判断"是否充分"的主观性和无限循环风险。

### 2. 答案优先 vs 报告优先的明确分流（node-DeepResearch）
node-DeepResearch 明确声明"不优化长篇报告，专注找正确答案"。这一设计哲学启示：Deep Research 应支持两种模式——快速答案模式（Search-Read-Reason 循环）和深度报告模式（Plan-Execute-Reflect 完整流程）。

### 3. 视角引导提问（STORM）
从相似主题的已有文章中发现多视角，用视角控制提问质量。这比直接让 LLM"生成研究问题"更系统、更全面。

### 4. 模拟对话研究（STORM）
编辑-专家对话模型，使 LLM 能基于新信息持续追问。比单次批量提问更自然、更深入。

### 5. 思维导图知识组织（Co-STORM）
层次化概念结构，建立人机共享概念空间。降低长研究的认知负荷，也提供了报告结构的天然骨架。

### 6. Compression 独立环节（open_deep_research）
将研究发现压缩为精炼上下文作为独立步骤，而非混在摘要中。解决长上下文 token 溢出，同时保留关键信息。

### 7. 多模型分工（open_deep_research / STORM）
Summarization 用 mini 模型、Research 用强模型、Compression 用强模型、Final Report 用强模型。精细的成本-质量平衡。

### 8. MCP 混合检索（GPT Researcher）
RETRIEVER=tavily,mcp 一行配置同时启用 Web 搜索和私有数据源（GitHub、数据库等）。

### 9. 本地文档研究（GPT Researcher）
DOC_PATH 支持 PDF/TXT/CSV/Excel/MD/PPT/Word 本地语料，研究不仅限于 Web。

### 10. CLI-backed Providers（DeerFlow）
直接复用 Codex CLI / Claude Code 的 OAuth 认证，无需单独配置 API Key。

### 11. 沙箱执行（DeerFlow）
E2B + Kubernetes 双沙箱，安全执行代码和数据操作——研究可包含"运行代码验证假设"。

### 12. 学术源垂直集成（OpenResearcher）
arXiv 文献检索，适合学术研究场景——通用 Web 搜索无法替代学术文献。

### 13. OpenAI-compatible API Server（node-DeepResearch）
一行 npm run serve 将深度研究能力暴露为标准 API，任何 OpenAI 兼容客户端可直接调用。

### 14. 内联图像生成（GPT Researcher）
Nano Banana 在研究阶段预生成插图，报告视觉化——纯文本报告的差异化升级。

### 15. make doctor / make support-bundle（DeerFlow）
内置环境诊断和问题报告工具，降低部署和排障门槛。

## 对 deep-research-ultra skill 的改进建议（具体到代码模块）

基于以上调研，对 deep-research-ultra skill 提出以下改进建议，按优先级排序：

### 建议 1：引入双模式架构（高优先级）

参考项目：node-DeepResearch（答案优先）+ GPT Researcher（报告优先）。改进模块：SKILL.md 触发层加主流程编排。具体方案：快速答案模式为 Search 到 Read 到 Reason 循环，Token Budget 驱动终止，输出简洁答案加 footnote 引用，适用于事实性问题、快速验证。深度报告模式为 Plan 到 Execute（并行多源）到 Compress 到 Reflect 到 Report 完整流程，适用于综述、调研、论文写作。在 SKILL.md 中根据查询类型自动路由：短问题/事实核查走快速模式，"调研/综述/分析"走深度模式。也允许用户显式指定。

### 建议 2：多模型分工策略（高优先级）

参考项目：open_deep_research（4 模型分工）+ STORM（5 模型分工）。改进模块：LLM 配置模块。具体方案：规划模型（Planning）用强推理模型（如 o3/Claude Sonnet）生成研究问题和大纲；搜索摘要模型（Summarization）用快速模型（如 gpt-4.1-mini/Haiku）摘要搜索结果，降低成本；压缩模型（Compression）用强模型压缩研究发现为精炼上下文；反思模型（Reflection）用强推理模型判断研究充分性；报告模型（Report）用强长文本模型撰写最终报告。通过环境变量配置各环节模型，默认使用单一模型但支持分工优化。

### 建议 3：Compression 独立环节（高优先级）

参考项目：open_deep_research。改进模块：研究流程中间件。具体方案：在"执行研究"和"撰写报告"之间增加独立的 Compression 步骤。执行阶段收集的原始信息可能非常冗长，Compression 步骤将其压缩为结构化精炼上下文（保留关键事实加来源），报告阶段基于压缩后上下文撰写，避免 token 溢出。这解决了"研究越深，上下文越长，报告质量下降"的问题。

### 建议 4：视角引导提问（中优先级）

参考项目：STORM。改进模块：规划阶段的问题生成。具体方案：不直接让 LLM"生成研究问题"，而是先搜索相似主题的已有文章/报告，从中提取不同视角（如技术视角、商业视角、用户视角、批评视角），基于视角生成针对性问题。这比单次提问更系统、更全面。

### 建议 5：递归树状探索（中优先级）

参考项目：GPT Researcher Deep Research。改进模块：研究执行引擎。具体方案：可配置 depth（深度）和 breadth（广度），每个分支评估信息充分性，不充分则递归深入子主题，跨分支上下文传递避免重复研究，并发处理各分支加速结果。

### 建议 6：MCP 混合检索（中优先级）

参考项目：GPT Researcher。改进模块：数据源配置。具体方案：支持 RETRIEVER=tavily,mcp 配置，同时启用 Web 搜索和 MCP 私有数据源。MCP 可接入 GitHub、数据库、Notion 等，实现"Web 加私有数据"混合研究。

### 建议 7：评测集成（中优先级）

参考项目：open_deep_research（Deep Research Bench）。改进模块：evals/evals.json。具体方案：参考 Deep Research Bench 的 100 个 PhD 级任务（50 英文 + 50 中文），在 evals.json 中增加 RACE 评分样本，使用 LLM-as-a-judge 量化研究质量，建立质量基线持续优化。

### 建议 8：本地文档研究（低优先级）

参考项目：GPT Researcher（DOC_PATH）。改进模块：数据源扩展。具体方案：支持 DOC_PATH 环境变量，指向本地文档目录。支持 PDF/TXT/CSV/Excel/MD/PPT/Word 格式。研究不仅限于 Web，可基于用户自有语料。

### 建议 9：学术源集成（低优先级）

参考项目：OpenResearcher（arXiv）。改进模块：数据源扩展。具体方案：集成 arXiv API 作为学术文献检索源。对于学术研究查询，自动启用学术源。区别于通用 Web 搜索的学术研究能力。

### 建议 10：报告视觉化（低优先级）

参考项目：GPT Researcher（Nano Banana 内联图）。改进模块：报告生成。具体方案：在报告生成阶段，识别可视化机会，调用图像生成 API 创建内联插图。提升报告可读性和专业度。

### 建议 11：OpenAI-compatible API 模式（低优先级）

参考项目：node-DeepResearch。改进模块：部署模式。具体方案：提供 serve 模式，将深度研究能力暴露为 OpenAI 兼容 API。任何 OpenAI 兼容客户端可直接调用，扩大适用场景。

### 建议 12：可观测性内置（低优先级）

参考项目：DeerFlow（LangSmith/Langfuse/Monocle）+ GPT Researcher（LangSmith）。改进模块：日志与追踪。具体方案：内置 LangSmith/Langfuse 追踪支持，通过环境变量开关。提供研究过程的可视化追踪，便于调试和优化。

## 总结

本次调研覆盖了 13 个深度研究开源项目，从 22k star 的 GPT Researcher 到学术性的 STORM，从字节跳动的 DeerFlow 到 Jina 的 node-DeepResearch。核心发现：

1. 方法论已趋同：Plan-Execute-Reflect 迭代循环是事实标准，但各项目在反思深度、终止条件、模型分工上有显著差异。

2. 两条路线分化：报告优先（GPT Researcher/STORM/open_deep_research）生成结构化长报告；答案优先（node-DeepResearch）迭代找正确答案，不追求长文。

3. 数据源是护城河：STORM 的 10 种检索器、GPT Researcher 的 MCP 生态、DeerFlow 的 InfoQuest 自有搜索——数据源丰富度直接决定研究质量。

4. 评测标准化：Deep Research Bench（100 PhD 任务加 RACE 评分）已成为事实标杆，open_deep_research 的评测结果表极具参考价值。

5. 本地化趋势：local-deep-researcher 推动完全本地运行，适合隐私敏感场景。

6. DeerFlow 的进化启示：从单一 Deep Research 进化为 Super Agent Harness，Deep Research 成为可插拔 Skill——这可能是未来方向。

对 deep-research-ultra skill 而言，最值得借鉴的三个改进是：双模式架构（答案优先加报告优先）、多模型分工加 Compression 独立环节（成本优化加上下文管理）、视角引导提问（系统性提升研究问题质量）。
