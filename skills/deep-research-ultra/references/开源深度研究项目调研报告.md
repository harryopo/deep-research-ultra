## 一、执行摘要

本轮调研覆盖任务列出的 10 个候选项目，**实际确认 9 个有效项目**（Skywork AI 仅 27 stars，OpenResearcher/SciOpenAgent 在 GitHub 未找到独立仓库）。开源深度研究生态在 2025-2026 年呈现三大演进方向：

1. **Super Agent Harness 化**：以 DeerFlow 2.0（79.5k stars，登顶 GitHub Trending）为代表，从单一"深度研究 Agent"升级为可编排子 Agent、沙箱、记忆、技能的超级智能体框架。
2. **多 Agent 协作 + 训练范式创新**：以 Tongyi DeepResearch（19.8k stars，11 篇论文）、OWL（20.1k stars，GAIA #1 69.09 分）为代表，把"搜索-合成"升级为"端到端 RL 训练 + 多 Agent 工具协作"。
3. **轻量递归范式与可复用最小实现**：以 dzhng/deep-research（<500 LoC，递归 breadth/depth 参数）为代表，证明深度研究可以极简且可读。

**总 stars 加总**：约 26 万 stars，其中 DeerFlow、STORM、GPT Researcher、HuggingFace smolagents、camel-ai/owl 五个项目是社区共识的"参考样板"。

**架构设计：递归深度研究（单 Agent）**
- **目标：<500 LoC 的最简深度研究实现**（透明可读，便于二次开发）
- 输入三参数：`Query + Breadth + Depth`
- Mermaid 流程图清晰展示递归机制

**核心方法论（递归探索）**
```
Deep Research(query, breadth, depth)
  → SERP Queries（生成多个搜索查询）
  → Process Results
    → Learnings（学习要点）
    → Directions（下一步研究方向）
  → if depth > 0:
      Next Direction = Prior Goals + New Questions + Learnings
      → Deep Research(new context, breadth, depth-1)  # 递归
    else:
      → Markdown Report
```

**数据源策略**
- **Firecrawl API**（web search + content extraction，支持 self-hosted）
- LLM：**OpenAI o3-mini**（默认）或 **DeepSeek R1**（通过 Fireworks，自动切换）
- 支持自定义 OpenAI-compatible endpoint（OpenRouter、Gemini、本地 LLM 等）

**创新特性**
- **breadth/depth 参数化递归**（breadth=3-10，depth=1-5）
- **Concurrent Processing**：并行处理多搜索与多结果
- **Smart Follow-up**：生成追问以精确化研究方向
- **ConcurrencyLimit 可调**（`CONCURRENCY_LIMIT` 环境变量）
- **社区 Python 实现**：https://github.com/Finance-LLMs/deep-research-python

**代码质量与可维护性**
- <500 LoC，极简
- TypeScript + Node.js
- Docker 支持
- Mermaid 流程图（README 内）

**活跃度**

## 五、可集成模式总结（10 个可直接集成模式）

### 模式 1：递归深度探索（breadth/depth 参数化）
**来源**：dzhng/deep-research
**核心**：将研究建模为 `DeepResearch(query, breadth, depth)` 递归函数，每轮累积 Learnings + Directions，depth 控制递归深度，breadth 控制并行查询数。
**集成方式**：
```python
async def deep_research(query, breadth=4, depth=2, prior_learnings=[]):
    queries = await generate_serp_queries(query, breadth)
    results = await process_results(queries)
    learnings, directions = extract(results)
    if depth > 0:
        next_direction = compose(prior_learnings + learnings, directions)
        return await deep_research(next_direction, breadth, depth-1, prior_learnings + learnings)
    return generate_markdown_report(learnings)
```
**适用场景**：可调强度的研究任务、需要可控 cost/quality 权衡的场景。

### 模式 2：多 LLM 角色分工
**来源**：langchain-ai/open_deep_research（4 角色）、STORM（6 LM 配置）、GPT Researcher（双模型）
**核心**：不同子任务用不同模型，cheap model 处理摘要/爬虫摘要，powerful model 处理最终报告。
**集成方式**：
```yaml
models:
  summarization: openai:gpt-4.1-mini  # 摘要搜索结果
  research:       openai:gpt-4.1       # 驱动搜索 Agent
  compression:    openai:gpt-4.1       # 压缩研究发现
  final_report:   openai:gpt-4.1       # 最终报告
  # 可扩展：question_asker / outline_gen / article_polish
```
**适用场景**：成本敏感、需要 cost/quality 平衡的生产环境。

### 模式 3：Perspective-Guided 多视角提问
**来源**：stanford-oval/storm
**核心**：不直接让 LLM 提问，而是先从相似主题的现有文章中发现不同视角，用视角控制提问过程；再模拟 writer-expert 对话，LLM 在对话中更新理解并追问。
**集成方式**：
```python
perspectives = discover_perspectives(topic)  # 调研相似主题文章
for perspective in perspectives:
    conversation = simulate_conversation(
        writer=writer_agent,
        expert=topic_expert_agent(perspective),
        retriever=internet_search
    )
    # conversation 过程中 expert 不断追问 + 更新理解
```
**适用场景**：需要广覆盖、多观点平衡的研究（避免单一视角偏见）。

### 模式 4：Super Agent Harness 编排（sub-agents + memory + sandbox + skills）
**来源**：bytedance/deer-flow 2.0
**核心**：将深度研究封装为可扩展 Skill，由 Super Agent 编排 sub-agents、memory、sandbox 完成 long-horizon 任务。
**集成方式**：
```yaml
harness:
  sub_agents:
    - name: researcher
      model: deepseek-v3.2
      skills: [search, scrape, summarize]
    - name: writer
      model: kimi-2.5
      skills: [outline, draft, polish]
  memory:
    long_term: sqlite  # or postgres
    compaction: manual  # 手动 context compaction
  sandbox:
    type: docker
    file_system: persistent
```
**适用场景**：长程任务（minutes-to-hours）、需要代码执行与文件持久化的复杂研究。

### 模式 5：MCP Server 集成 + 多搜索 API 抽象层
**来源**：gpt-researcher、langchain-ai/open_deep_research、deer-flow、owl
**核心**：将搜索能力抽象为统一接口，支持 Tavily / DuckDuckGo / Bing / Google / Searx / You.com / Brave / Serper / Azure AI / Firecrawl 等多后端；同时支持任意 MCP server 作为数据源。
**集成方式**：
```python
class SearchProvider(ABC):
    @abstractmethod
    async def search(self, query: str, k: int) -> List[SearchResult]: ...

class TavilySearch(SearchProvider): ...
class BingSearch(SearchProvider): ...
class MCPSearch(SearchProvider):  # 任意 MCP server
    def __init__(self, mcp_config: dict): ...
```
**适用场景**：需要灵活切换/组合数据源、避免 vendor lock-in。

### 模式 6：Planner + Execution Agents 双 Agent 模式
**来源**：assafelovic/gpt-researcher
**核心**：Planner 生成研究问题，Execution Agents 并行抓取，最后 Planner 过滤聚合。
**集成方式**：
```python
planner = PlannerAgent(model="gpt-4-turbo")
questions = planner.generate_questions(query)  # objective opinion 形成
executors = [ExecutionAgent(model="gpt-3.5-turbo") for _ in questions]
results = await asyncio.gather(*[exec.search(q) for exec, q in zip(executors, questions)])
summarized = [summarize(r) for r in results]
report = planner.aggregate(summarized)  # filter + aggregate
```
**适用场景**：3 分钟 ~$0.1 的快速研究任务。

### 模式 8：IterResearch "Heavy" 模式（test-time scaling）
**来源**：Alibaba-NLP/Tongyi DeepResearch
**核心**：双推理范式——ReAct（标准）+ IterResearch（test-time scaling，迭代研究以解锁最大性能）。
**集成方式**：
```python
def iter_research_heavy(query, max_iterations=10):
    state = {"query": query, "findings": [], "confidence": 0}
    for i in range(max_iterations):
        result = react_inference(state)
        state["findings"].extend(result.findings)
        state["confidence"] = assess_confidence(state)
        if state["confidence"] > threshold:
            break
        state["query"] = refine_query(state)  # 迭代精化
    return synthesize(state)
```
**适用场景**：需要 maximum performance ceiling 的高难度研究（牺牲速度换质量）。

### 模式 9：Context Summarization + Proactive Context Management
**来源**：Alibaba-NLP（ReSum 论文 + AgentFold 论文）、deer-flow（Manual Context Compaction）
**核心**：长程任务中主动压缩上下文，避免 context 爆炸；proactive（前瞻性）管理而非被动截断。
**集成方式**：
```python
class ContextManager:
    def __init__(self, max_tokens=128000, compress_threshold=0.8):
        self.history = []
    def add(self, message):
        self.history.append(message)
        if self.token_count() > self.max_tokens * self.compress_threshold:
            self.proactive_compress()
    def proactive_compress(self):
        # 识别低信息密度片段并摘要
        old = self.history[:len(self.history)//2]
        summary = llm_summarize(old)
        self.history = [summary] + self.history[len(self.history)//2:]
```
**适用场景**：128K+ context 的长程研究任务。

## 六、对 deep-research-ultra v5.0 的具体优化建议

基于上述调研，建议 deep-research-ultra v5.0 从以下 8 个维度优化：

### 建议 1：采用"Super Agent Harness + 递归探索"混合架构
**依据**：DeerFlow 2.0（Super Agent Harness）+ dzhng/deep-research（递归）的双重启发
**实施**：
- 外层用 Super Agent Harness 编排（sub-agents + memory + sandbox + skills）
- 内层用 breadth/depth 参数化递归（控制研究深度与广度）
- 这样既支持 long-horizon 任务，又能精细控制 cost/quality

### 建议 2：实现 4 角色 LLM 分工 + 多 Provider 路由
**依据**：langchain-ai/open_deep_research 的 4 角色模式 + DeerFlow 的多 Provider YAML schema
**实施**：
```yaml
models:
  summarization: {provider: openai, model: gpt-4.1-mini}
  research:      {provider: deepseek, model: deepseek-v3.2}
  compression:   {provider: openai, model: gpt-4.1}
  final_report:  {provider: kimi, model: kimi-2.5}
  question_asker: {provider: openrouter, model: gemini-2.5-flash}
```
- 支持 OpenAI / DeepSeek / Kimi / OpenRouter / vLLM / Claude / Gemini 等
- 不同角色可路由到不同 Provider（成本最优）

### 建议 3：内置 Perspective-Guided 多视角提问模块
**依据**：STORM 的核心创新（直接 prompt LLM 提问效果差，多视角控制效果好）
**实施**：
- Stage 1：从相似主题的现有文章中发现 N 个视角
- Stage 2：每个视角启动一个 Simulated Conversation（writer + expert + retriever）
- Stage 3：聚合多视角对话的 Learnings
- 这是与 GPT Researcher / Open Deep Research 的差异化竞争力

### 建议 4：集成 MCP Server + 10+ 搜索后端抽象层
**依据**：STORM（10+ RM）+ GPT Researcher（6+ API）+ DeerFlow（MCP）+ OWL（MCPToolkit）
**实施**：
- 抽象 `SearchProvider` 接口，内置：Tavily / Bing / Google / DuckDuckGo / Searx / You.com / Brave / Serper / Azure AI / Firecrawl
- 支持 MCP server 作为数据源（用户可挂载私有 MCP）
- 支持 VectorRM（用户文档 grounding）

### 建议 5：实现 Dynamic Mind Map + Context Summarization
**依据**：STORM（Mind Map）+ Tongyi DeepResearch（ReSum / AgentFold 论文）+ DeerFlow（Manual Context Compaction）
**实施**：
- **Dynamic Mind Map**：层级概念结构，支持可视化导航，作为 shared conceptual space
- **Proactive Context Summarization**：识别低信息密度片段并主动摘要，区别于被动截断
- 二者结合解决长程任务的 context 管理难题

### 建议 6：引入 IterResearch "Heavy" 模式（双推理范式）
**依据**：Tongyi DeepResearch 的 ReAct + IterResearch 双模式
**实施**：
- **Light 模式**（默认）：单轮 ReAct，快速响应
- **Heavy 模式**（可选）：多轮 IterResearch，迭代精化 query + confidence 评估，直到 confidence > threshold 或 max_iterations
- 用户可按需切换（cost vs quality 权衡）

### 建议 7：集成 Sandbox + File System + Long-Term Memory
**依据**：DeerFlow（Sandbox & File System + Long-Term Memory）+ Tongyi DeepResearch（SandboxFusion）
**实施**：
- **Sandbox**：Docker 容器化代码执行（参考 SandboxFusion）
- **File System**：持久化中间结果、引用文件、生成的报告
- **Long-Term Memory**：sqlite/postgres + 可选 Redis 缓存
- 支持 checkpoint（中断恢复）

### 建议 8：接入 Deep Research Bench + GAIA 双评估体系
**依据**：langchain-ai/open_deep_research（Deep Research Bench #6）+ OWL（GAIA #1）+ HuggingFace（GAIA 55%）
**实施**：
- **Deep Research Bench**：100 PhD 级任务（50 英文 + 50 中文），RACE score（LLM-as-a-judge）
- **GAIA benchmark**：通用 Agent 能力评估
- 每次发版自动跑评估，结果公开（参考 langchain-ai 的透明度）
- 评估脚本：`tests/run_evaluate.py` + LangSmith 集成

## 七、总结

### 7.1 三大演进趋势

1. **从"Agent"到"Super Agent Harness"**：DeerFlow 2.0（79.5k stars）证明，社区已经接受"深度研究 = 可编排 sub-agents + memory + sandbox + skills 的 Harness"这一范式。单纯的"Planner + Executor"已不够。

2. **从"框架"到"训练型 Agentic LLM"**：Tongyi DeepResearch（17 篇论文）与 OWL（GAIA #1）证明，端到端 RL 训练 + 多 Agent 协作是性能上限的突破口。框架的护城河正在被"训练方法论"取代。

3. **从"单 Agent"到"多视角 + 多 Agent + 多 LLM"**：STORM 的多视角提问、langchain-ai 的 4 角色分工、OWL 的 Workforce 协作，都指向同一方向——分工与并行是 scale 的关键。

### 7.2 deep-research-ultra v5.0 的差异化定位建议

基于本轮调研，建议 v5.0 定位为：
> **"递归深度研究 + Super Agent Harness + 多视角提问"三合一架构**
> - 比 dzhng/deep-research 更强大（Harness 编排 + 沙箱 + 记忆）
> - 比 DeerFlow 更聚焦（专注深度研究，不做通用 Super Agent）
> - 比 STORM 更现代（MCP 集成 + 多 Provider 路由 + 递归探索）
> - 比 GPT Researcher 更深入（多视角提问 + Mind Map + Context Summarization）
> - 比 Tongyi DeepResearch 更轻量（无需训练自有模型，复用开源 LLM）

### 7.3 关键风险与注意事项

1. **DeerFlow 已 79.5k stars**，直接竞争风险高，差异化必须清晰
2. **STORM 进入维护期**（push 2025-09-30），可考虑 fork 其 dspy 模块化设计
3. **Tongyi DeepResearch 也进入维护期**（push 2026-02-27），但其 17 篇论文方法论可自由借鉴
4. **camel-ai/owl 的 license 为 null**，集成其 Toolkit 时需谨慎确认许可
5. **SciOpenAgent/OpenResearcher 不存在**，任务描述需更正
6. **Skywork AI 开源价值极低**，不建议作为参考
