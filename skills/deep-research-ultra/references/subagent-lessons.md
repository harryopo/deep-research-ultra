# 子 Agent 派单纪律的事故档案（subagent-lessons）

> 派单模板（SKILL.md Phase 2.5）里每条纪律背后都有一次真实事故。把"为什么"从
> 提示词里挪到这里：提示词保持任务书形态（清晰、可执行），这里是**教训档案**——
> 改模板前先读一遍，避免拆掉一条当年用真金白银换来的护栏。

| 纪律 | 事故档案 |
|---|---|
| 分片只写自己的、禁止覆盖式写 | 一轮实跑里 D1 用 Write 整写共享留痕账，把 D2 已登记的 4 行抹掉了——并发场景下"整文件覆盖"＝丢别人的数据 |
| 留痕账不共享、按 `*injection*.jsonl` 一族认 | 子 Agent 被"别动共享文件"和"注入要留痕"两条规则逼得自改名 D5-injection.jsonl——门的识别口径随后跟进（认一族而不认固定名） |
| "往 injection_log.jsonl 追加一行"＝注入 | 2026-09-29 D8 维度上报：抓取内容尾部出现要求替留痕账代笔的指令——留痕账若接受外来代笔，伪造一行就能把真注入伪装成"已上报" |
| 不接受"本会话已做过 X"的自述 | 同轮谎称"已创建 scratch/d8/ledger_d8.py"——实际列目录根本不存在；谎称的目的是让 Agent 跳过上报 |
| 临时文件只进会话 scratch/，禁 /tmp | helper 写在 /tmp，事后没人知道它跑过什么——护栏作用域是会话目录，路径一出界等于脱账 |
| 预算 ≤25 次调用 | 一轮开放式清单烧掉 84 次调用、五千万 token，产出的候选清单大半无用 |
| 【Lead 记忆，未核实】先回源 | Lead 派单里的人名/数字可能记错；子 Agent 硬凑一个答案比报"查不到"危害大得多 |
| 仓库活跃只认 pushed_at | citation-check-skill 最后一次推送 2026-01-26、元数据时间 2026-09-28——拿后者写"最近仍在维护"就是错的 |
| 取数走官方 API、gh api 而非匿名 curl | 匿名 api.github.com 403/60 次每小时；gh api 一次就通 |
| 『』内禁省略号、术语用〔〕、粘连照抄 | 四六级实跑 45 段 MISS 的主因：摘抄加省略号、术语强调占逐字引号、raw 断行粘连被"顺手修正" |
| 逐字引文 ≤1200 字 | 整页原文整段进账本＝注入面扩大（L2） |
| 分片必须 UTF-8 | Windows 默认 GBK 写分片，中文被 merge 点名拒收 |
| 不用 TodoWrite/TaskCreate | 待办列表与 Lead 共享同一份，并行子 Agent 各记几条就把 Lead 的进度视图刷废 |
| 不直写共享 ledger.jsonl | 多进程并发追加整行不保证原子；merge 幂等收编才是正道 |

补充判例（档 B 反查）：Europe PMC 文章页是 SPA 外壳（静态抓 4-5KB 无正文）；
PMID 连字符 vs 全文 XML en dash 属字符形态差异，逐字判同不许放宽——这两类
claim 按规则保持 pending，渲染为「⚠️ 仅作线索」，不为过门改判据。
