# 信息需求类型表（v6.51）

Lead 在 Phase 1 用它把"用户想要什么"翻译成"该搜哪几维"。
**先认类型，再选维度**——反过来（从主题想能拆成哪几块）会搜回一堆
"事实正确但答不上用户问题"的东西。

## 为什么要有这张表

用户输入"调研开源考研软件"，这句话里没有任何决策信息：

- 可能是**要选型报志愿** → 关心维护状态、许可证、社区活跃度
- 可能是**要做毕设** → 关心文档质量、技术栈、上手难度
- 可能是**要在产品里集成** → 关心 API 稳定性、部署成本、许可合规

同一句话，三种目的的调研方向几乎没有交集。不问清楚就开搜，搜回来的
材料再详实也答不上他真正想问的那件事。

## 五类信息需求

每类给出：识别信号、**该问的维度**、**不相关的维度**（省下的是检索预算）、
以及**该问用户的第一个问题**。

---

### 类型 1 · 决策选型（"该选哪个"）

**识别信号**：哪个好 / 怎么选 / 推荐 / 对比 / vs / 值不值得 / 替代

**该问维度**
- 候选清单与其覆盖度（主流选项有哪几个，各自擅长什么）
- **维护状态**：`pushed_at` 频率、issue 响应、未归档确认（比 star 有用得多）
- **许可证**：能否商用、有无 copyleft 传染性
- 社区活跃：贡献者数、issue 关闭率、是否有 bus factor 风险
- 迁移成本：换过去要改什么、数据能否带走
- 已知风险与失败案例

**不相关**：论文里的性能对比（除非是要写论文）、历史沿革、作者背景

**第一个问题**："你是要**选一个**（那我们重点比维护度和许可证），还是想
**了解这个领域**（那重点讲它怎么工作的）？"

**结论形态**：明确推荐 + 理由 + 什么情况下不推荐它

---

### 类型 2 · 认知理解（"它是什么、怎么工作的"）

**识别信号**：是什么 / 原理 / 怎么实现 / 机制 / 区别 / 教程

**该问维度**
- 核心机制与关键抽象（它把问题拆成了哪几层）
- 与替代方案的设计取舍（为什么这么做而不是那么做）
- 典型使用形态与最小可用样例
- 边界条件：不适用什么

**不相关**：许可证合规细节、star 数、竞品排名

**第一个问题**："你想**理解它怎么工作**，还是想**用它做某个事**？"

**结论形态**：机制说明 + 什么时候该用它

---

### 类型 3 · 落地实施（"我要用它做 X"）

**识别信号**：我要 / 上手 / 部署 / 集成 / 迁移 / 接进

**该问维度**
- 前置条件与依赖（版本、网络、硬件门槛）
- 官方文档与示例代码的可用性
- 真实踩坑记录（issue 里问最多的问题）
- 部署形态与运维成本
- 与现有技术栈的兼容性

**不相关**：学术评分、引用量、团队背景

**第一个问题**："你打算在**什么环境**用它？（本地 / 生产 / 集成进已有系统）"

**结论形态**：可执行步骤 + 已知风险点

---

### 类型 4 · 产品规划（"市场上有什么机会"）

**识别信号**：市场 / 竞品 / 格局 / 趋势 / 机会 / 值得做吗

**该问维度**
- 主要玩家与各自的定位差异
- 需求侧的真实痛点（用户抱怨什么）
- 已被验证的商业模式
- 未被满足的需求（空白点在哪）
- 监管与合规约束

**不相关**：单个库的技术细节（除非它就是竞品主体）

**第一个问题**："你想看**已有玩家怎么打**（格局），还是看**还没被满足的需求**（机会）？"

**结论形态**：格局判断 + 切入点建议

---

### 类型 5 · 风险审查（"这东西有什么坑"）

**识别信号**：风险 / 安全 / 靠谱吗 / 会被攻击 / 隐私 / 坑

**该问维度**
- 已知漏洞与披露记录
- 威胁模型与攻击面
- 数据处理与隐私合规
- 单点故障与依赖风险
- 维护者响应速度（漏洞多久修）

**不相关**：性能优化、部署教程

**第一个问题**："你担心的风险是**安全漏洞**，还是**供应商/维护风险**（作者跑路、停更）？"

**结论形态**：风险清单 + 缓解措施

---

## 维度不是模板，是起点

拿到类型后按上表起步，然后**按用户的实际场景收窄或加深**。

例：类型 1 选了"该选哪个"，但用户是高校选课平台而非个人学习者 →
把"上手难度"换成"能否私有化部署"，因为场景变了。

判断标准只有一个：**搜回来的每一维，都要能回答用户最开始那个问题。**
答不上就是废维度。

## 记录进账本

类型判定要写进计划，让后续子 Agent 知道每条证据是"为哪个问题服务的"。
否则容易出现"搜了一堆论文但没有一条对着用户的问题"——v6.48 实跑
（AI Agent 方向）就出现过：论断本身都对，但用户真正问的"该选哪个框架"
始终没有一句直接回答。
