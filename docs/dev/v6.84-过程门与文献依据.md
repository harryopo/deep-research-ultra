## 二、文献说的（5 篇，全部一手）

### 1. Huang et al. 2024, "Large Language Models Cannot Self-Correct Reasoning Yet"（ICLR 2024）

LLM 在**没有 oracle 标签**时无法可靠地自我纠正推理；用 oracle 标签引导时
"改进"才出现，oracle 拿掉改进就消失。而且已有研究里普遍存在两个问题：
用 oracle 信息（不现实的框架）、与等成本基线比较不公平。

> **对本项目的直接含义**：让 agent「再检查一遍」不是解法。

### 2. "On the Self-Verification Limitations of LLMs on Reasoning and Planning Tasks"（2402.08115）

在 Game of 24、Graph Coloring、STRIPS Planning 三个域上：self-critique 显著
**降低**性能；backprompt 次数增加时输出质量**持续退化**。作者结论是应该做成
**LLM-Modulo**——验证交给**外部可靠系统**。

> **含义**：自我验证不是"弱一点的好办法"，是有害的。加反思轮次可能更糟。

### 3. "Reliability without Validity"（2606.19544）—— 这篇是决定性的

- **一致性–偏置悖论**：test–retest 可靠性 α > 0.95 可以与严重位置偏置**并存**。
  原文：*"a judge that deterministically favors position A across runs would
  achieve a perfect test-retest score, but would also exhibit maximum-possible
  position bias."*
- **Kappa 通胀**：21 个模型**全部**，原始一致率把随机校正后的区分度**高估 33–41pp**。
  「报告 85% 一致」的评判者，实际 κ ≈ 0.48。
- 位置偏置的 flip rate 跨模型 25%–50%。

> **含义**：**高可复现性 ≠ 有效度**。我重读自己的产出、觉得"没问题"，
> 那是极高的重测一致性配极低的有效度。这条精确描述了我"再检查一遍"时的状态。

### 4. "Rethinking Verification for LLM Code Generation"（2507.06920）—— 同质化陷阱

PCA 分析显示 **LLM 产生的错误高度聚集**（系统性弱点），而人的错误分散。
由 LLM 生成的测试做成的验证器因此有**同质盲区**，称为 **homogenization trap**。

> **含义**：**同一个模型既生成又验证，两边错在同一个方向**，而且错得很一致。
> 所以"让 agent 自己审自己的产出"在原理上就不该被期待有效。

### 5. Cemri et al. 2025, "Why Do Multi-Agent LLM Systems Fail?"（MAST, NeurIPS 2025）

200 条 trace、7 个 MAS 框架、6 位专家标注者，κ=0.88。**14 种失效模式 / 3 大类**，
带实测占比。作者明确说：**改进基座模型能力不足以解决 MAST 的全部问题**。

关键占比：

| 模式 | 占比 |
|---|---|
| FM-1.3 步骤重复 | **17.14%** |
| FM-2.2 带着错误假设继续而不去澄清 | **11.65%** |
| FM-1.1 未遵守任务规范 | 10.98% |
| FM-1.5 未能识别任务完成 | 9.82% |
| FM-2.3 任务偏航 | 7.15% |
| FM-1.3 前的 2.6 推理-动作不匹配 | — |

## 四、反直觉的推论（这版最重要的一句）

既然：
- 自我验证**有害**（Huang / 2402.08115）
- 自我验证**无效**（高重测一致性 + 低有效度，2606.19544）
- 自我验证**原理上不该有效**（同质化陷阱，2507.06920）

那么**任何形式的"让 agent 再审视一遍自己"都不该被加进来**——包括我一度想写的
「交付前让 agent 复述一遍自己的假设」这类条款。

文献指向的唯一可靠方向是：**验证必须来自结构上不同、失效模式不相关的东西**。
在本项目里就是两种：

1. **可执行的机械检查** —— 脚本要么跑得起来要么跑不起来，没有"感觉"
2. **把产出重新呈现为外部物件** —— 论文称之为 addressability：
   把逐字相同的断言换个外部角色标签重新呈现，纠正率提升 **23–93pp**，
   而"要求自己怀疑自己"的提示词只有 0–23%。

第 2 条正好解释了一件事：**为什么"我去查了一下磁盘"和"我印象是这样"的结果
天差地别**。前者是外部物件，后者是同一个模型的同一次推理。

这正是 2606.19544 描述的状态：**高可复现性（我记得那些数字、每次说得一样）
配低有效度（没人能重跑）**。

## 六、所以这一版改什么

只做文献支持、且能机械验证的三件：

1. **把产出 CHANGELOG 数字的分析脚本纳入版本控制**，并加测试确保可跑通。
   这是 addressability 的落地：让结论挂在一个可复算的物件上。
2. **加 `preflight.py` 过程门** —— 对 Lead 的工作做机械检查，
   而不只是对报告做。这是 LLM-Modulo 的直接应用。
3. **SKILL.md 加一条带文献依据的禁止行为**：量化结论必须挂可复算脚本。

**明确不加的**：任何形式的自我复述/自我审查环节。文献说它有害。

## 七、这次的边界

- 本项目至今的 1179 项测试，全都是对**产出**的检查（报告、账本、戳、文档数字）。
  **对过程零检查** —— 这就是缺口所在。

  纪律条款 + 文献提醒。**别把过程门说成万能的**。
- 五篇文献都是别人的结论，我没有重跑它们的实验。它们在这里的作用是
  **排除一个方向**（自我验证），而不是证明另一个方向必然可行。
